# Регламенты лиг и пирамиды

**Статус на 2026-11-21.** Два ассета-снимка описывают все лиги мира, которые есть в базе:
сезонные окна, фазы, стыки и границы дивизионов. Это данные, а не движок: загрузчик и
тест есть только у регламентов, пирамиду пока никто не читает. Полная модель стадий
(форматы 58 лиг) исследована, но в ассет ещё не закодирована — см. ниже.

Спеки: `docs/superpowers/specs/2026-11-20-career-season-formats.md` (семантика форматов),
`2026-11-20-career-data-assets.md` (правила ассетов). Аудит-след — `docs/research/`.
Пайплайн, которым эти данные попадают в базу, — [[пайплайн-данных]].

## `assets/data/league_regulations.json`

284 лиги, ключ — id лиги из базы (`GB1`, `BRA1`, `FR5A`). Верхний уровень:
`_comment`, `_generated` (дата снимка), `_defaults` (окна-прокси), `leagues`.

| поле | смысл |
|---|---|
| `start_md`, `end_md` | окно сезона `MM-DD`, повторяется каждый год; `end_md < start_md` = переход через Новый год |
| `filled` | `start` / `end` / `start+end` — значение подставлено прокси-окном класса |
| `phases` | метка исследования `single` / `split` / `apertura_clausura` / `other`; после перехода на `format` остаётся только аудит-следом |
| `relegation` | `{slots, playoff}`; `slots: null` = число неизвестно (загрузчик отдаёт `-1`) |
| `tiebreak` | порядок тай-брейков (`points`, `goal_difference`, …) |
| `transfer_windows` | окна трансферов, если источник их назвал |
| `confidence` | `high` / `medium` / `low` — насколько источник близок к сезону |
| `inherited_from` | нижний дивизион скопировал окно верхнего, своего источника нет (170 записей) |
| `source`, `note` | ссылка на статью сезона и всё, что не влезло в поля |

Дефолты-прокси: `autumn` = 18.08–23.05 (52 лиги), `calendar` = 06.03–29.11 (24 лиги).
Уверенность: 213 `high`, 61 `medium`, 10 `low`. `phases` сейчас: 217 `single`, 40 `split`,
23 `apertura_clausura`, 4 `other`.

### Загрузчик `LeagueRegulations`

`scripts/data/league_regulations.gd` (`class_name LeagueRegulations`, статический кэш):

- `load_all()` / `last_error()` — разбор файла один раз на процесс;
- `record(id)`, `defaults()`;
- `window(id, year)` — реальные даты; год конца следует за началом при переходе через Новый год
  (`GB1` 2026 → 21.08.2026–30.05.2027);
- `window_for_season(id, season_start)`;
- `first_window_on_or_after(id, date)` — карьера начинается со свежего сезона: если окно этого
  года уже открылось, берётся следующее (июльская карьера в Бразилии стартует 28.01.2027);
- `next_window_start(id, season_start)` — тот же день и месяц годом позже;
- `season_end(id, season_start)` — день перед следующим окном; в согласованной модели это будет
  день перед **границей** сезона, а не перед окном (фаза 0, см. [[открытые-вопросы]]);
- `phase(id)`, `relegation_slots(id)`, `tiebreak(id)`.

### Форматы

Сейчас `format` в регламентах **нет**. Исследование закрыто: 58 лигам нужна модель стадий
(24 с меткой `apertura_clausura`, из них реально фазовых 17, плюс 37 сплитов и группы),
остальные 219 — обычная одна таблица. Модель (стадии `league`/`group`/`knockout`, `entrants`,
`carry`, `bonus`, условные стадии, повышение/вылет клубами) описана в спеке форматов.
Когда данные лягут в ассет, `format.start_md`/`end_md` будут главнее строки, а строку
валидатор обяжет совпадать с форматом.

## `assets/data/league_pyramids.json`

284 лиги, 108 границ между уровнями, 106 стран. Уровни: 108 первых, 73 вторых, 41 третьих,
32 четвёртых, 10 пятых, 2 шестых и 18 молодёжных `level: 99` (в карьеру не входят).
Верхний уровень: `leagues`, `boundaries`, `conflicts`, `missing`.

Запись лиги: `level`, `size` (число клубов), `closed_up` / `closed_down` (движения нет,
например закрытая лицензионная лига), `format` — **грубая метка исследования**
(`single` 171, `groups` 44, `split` 38, `other` 9, `apertura_clausura` 14), не модель движка;
`playoff`, `country`, `confidence`.

Граница: `country`, `upper`, `lower`, `up`/`up_playoff`, `down`/`down_playoff`,
`allocation`, `selection`, `note`. Инвариант — **`up == down` на всех 108 границах**: уход
клубов из лиги равен приходу, размеры лиг не плывут. Исследование дало шесть несбалансированных
границ; четыре были разовыми структурными изменениями (Сербия 14→12, Тайвань, Новая Зеландия,
Аргентина 3→4), две — конфликтом источников (Албания, Иран), их уравняли с пометкой в `note`.
Разовое изменение записывается в `note`, а не в постоянную границу.

Параллельные лиги (три группы Serie C, региональные лиги Германии, группы N4/N5 Франции)
живут на одном уровне: граница считается уровень-в-уровень, а не лига-в-лигу. Лига, отдавшая
наверх `n` клубов, получает `n` обратно; география не моделируется. `conflicts` (72 страны) —
расхождения исследования с базой или форматом, `missing` — пустой.

## Известные дыры

- **Чили, 4-й уровень (`CL3A`)** и **Уругвай, 3-й уровень (`URC`)** на Трансфермаркте
  отсутствуют. Id в отчётах условные; выдумывать их нельзя, поэтому лиг в базе нет.
- **Новая Зеландия (`NZL1`)** — фаза чемпионата, а не отдельная лига; вне области.
- **Семь расхождений размера** между отчётом и снимком базы: Катар-2 8/12, Болгария-2 20/18,
  Эфиопия 20/18, Литва-2 18/16, Франция-4C 16/17, Франция-5H 14/13, Румыния-2 22/23.
  Решением 2026-11-21 истина — **база** (по ней собраны составы); отчёты не переписываются,
  расхождение остаётся пометкой «другой сезон».
- У пирамиды **нет загрузчика и теста** — данные лежат, инварианты никто не проверяет.
- `phases` в регламентах — метка исследования: у части `apertura_clausura` на самом деле одна
  таблица или зоны. Движку верить только будущему `format`.

## Как обновлять

Снимок, а не поток: раз в год ручной проход по `docs/research/season-windows/`,
`docs/research/pyramids/`, `docs/research/season-formats/`. Скрипты, которыми отчёты сведены в
ассеты, в репозиторий не кладутся (решение зафиксировано в спеке данных) — правится JSON,
`_generated` обновляется, тест перезапускается. После изменения состава базы (новая лига,
слияние, переезд клуба) пересчитываются `size` и `boundaries`, иначе пирамида врёт.
