# Пайплайн данных

**Статус на 2026-11-21.** Как лига, клуб или игрок попадают из Трансфермаркта в игру.
Скрипты-генераторы живут в отдельных проектах рядом; в репозитории лежат только сборочные
инструменты и правила. Итог — `data/databases/default/open_football.sqlite`, которую читает
[[каталог-команд]], и `canon.db` прототипа карьеры, которую читает [[карьера]].

Спеки: `2026-11-20-career-data-assets.md` (что читает игра), `2026-11-20-career-season-formats.md`
(форматы и календарь). Ассеты и их поля — [[регламенты-и-пирамиды]].

## Маршрут

```
Transfermarkt (HTML)
  → transfermarkt-api (:8001)
  → кэш скрапера  transfermarkt_scrapper/tm_cache.sqlite3
  → канон         transfermarkt_scrapper/data/canon/*.json
  → генераторы    ratings · faces · kits
  → импорт        tm-gf-import → database.sqlite
  → слияние       tools/build_open_football_db.py
  → open_football.sqlite + eligibility + manifest
```

`canon.db` собирается из того же канона отдельным шагом (`gf-career-prototype`). Обе базы
сливаются по transfermarkt-id, поэтому id — единственный ключ сквозь весь маршрут.

## Добавить лигу от начала до конца

Порядок, которым добавлены Регионаллига Север/Запад и пять групп французского N2.

1. **Найти настоящий id.** Старый id врёт: `RLN`/`RLW` — это Регионаллига 1963–74, современные —
   `RLN3`/`RLW3`; `CL3A` и `URC` на Трансфермаркте не существуют вовсе. Проверять заголовок
   `/x/startseite/wettbewerb/<id>`.
2. **Скачать клубы и составы.** API иногда падает на `/competitions/<id>/clubs` с `seasonId: null`
   (500). Обход: взять список клубов из HTML страницы соревнования и положить синтетический
   payload в кэш (`insert or replace into requests(url, status, payload, fetched_at)`), затем
   `fetch.clubs.club_profiles` и `fetch.rosters.club_rosters` — они уже читают кэш.
3. **Логотипы.** `download_images.download_club_logos_from_cache()` — лого клубов; лого лиги —
   `https://img.a.transfermarkt.technology/logo/header/<id в нижнем регистре>.png` →
   `data/images/leagues/<id>.png`.
4. **Канон.** `build_canon_from_cache.py`; он валидирует файлы по `canon_schema.json` и пишет
   счётчики.
5. **Рейтинги.** `generate.py` по всему канону (не только новым записям) — выход один на всех.
6. **Лица.** `generate_faces.py --leagues <список>` даёт только новые записи; их надо **слить**
   с `tm-gf-face-generator/out/specs.json` по id, не перезаписывая существующие. Кропы —
   `export_cutouts.py`, потом копия в `assets/faces/<player_id>.png`.
7. **Формы.** Генератор рендерит весь канон, включая сборные; в `kit-generator/out/all/`
   копируются только каталоги клубов новой лиги (иначе мусор на десятки тысяч файлов).
8. **Импорт.** `import.py … --db-only` пишет `database.sqlite` в staging; файл копируется в
   `data/databases/default/database.sqlite` (дерево данных — junction на
   `C:\Users\Egor\Desktop\projects\open_football_career\data`).
9. **Канон карьеры.** JSON канона копируется в `gf-career-prototype/data/json`, затем
   `python scripts\build_canon_db.py --json-dir data\json --ratings ..\ratings-generator\ratings_output.json --out canon.db`.
10. **Слияние.** `python tools\build_open_football_db.py`; печатает
    `countries / leagues / teams / players` и `clubs / national / fieldable`.
11. **Пост-импортные слияния.** `AR3R → AR3F` (37-клубный Torneo Federal A) и
    `CL2Z → CL2F` (14-клубная чилийская Сегунда) переносят клубы в `database.sqlite` **и**
    `canon.db`, называют целевую лигу и удаляют лишнюю строку. Пересборка из канона скрапера
    снова их раздваивает — шаг обязателен после **каждого** импорта.
12. **Картинки.** Гербы клубов — в `images_teams/<league_slug>/<club_slug>_logo.png` (тот путь,
    что лежит в `teams.logo_url`) и копия в `raster/teams_emblems/<tm_id>.png` для карьеры;
    формы — `<kit_url>_kit_01..06.png`; лого лиги — `images_competitions/<id>.png`;
    лица — `assets/faces/<tm_id>.png`.
13. **Ассеты и тест.** Строка в `league_pyramids.json` (уровень, размер, границы) и
    `league_regulations.json` (окно, фазы, источник); `godot --headless --path . -s
    res://tests/check_league_regulations.gd`; проверить размеры лиг в базе против пирамиды.

## Где игра читает картинки

| что | путь | читает |
|---|---|---|
| лого клуба в матче | `data/databases/default/<teams.logo_url>` | `UiAssets.team_logo` |
| формы | `data/databases/default/<teams.kit_url>_kit_01..06.png` | `KitTexture`/`UiAssets` |
| лого лиги | `data/databases/default/images_competitions/<league_id>.png` | `UiAssets.league_logo` |
| герб клуба в карьере | `data/raster/teams_emblems/<tm_id>.png` | `CareerClubInfo`, хаб, загрузка сейва |
| лицо игрока | `assets/faces/<tm_id>.png` | карточки игроков и состав |
| флаг страны | `data/databases/default/images_countries/<country_id>.png` | `UiAssets.flag` |

`data` — junction на общее дерево данных, `assets/faces` — junction на
`open_football_career/assets/faces`, обе папки вне git.

## Грабли

- **Пересборка откатывает слияния.** Любой импорт из канона возвращает `AR3R`/`CL2Z`; шаг 11
  повторять всегда, иначе в базе снова 18+19 и 12+2.
- **`import.py` пишет staging, а не игру.** Без копии `database.sqlite` в дерево данных слияние
  соберёт старую базу.
- **Для `canon.db` нужен `data/json`.** Скрипт прототипа читает JSON из `gf-career-prototype`,
  а не напрямую из скрапера.
- **Лица только по настоящим фото.** Заглушка-силуэт Трансфермаркта пропускается; у таких
  игроков остаётся силуэт, но `skincolor`/`hairstyle`/`haircolor` всё равно заполняются
  приоритетами по национальности и позиции. Покрытие фото — свойство источника: 95% у немецкой
  Регионаллиги, 24% у французского N2.
- **Один id на всё.** Игроки, клубы и сборные — числовой tm_id; лиги — код соревнования.
  Дубли «клуб + сборная» схлопываются при слиянии.
- **Исследование — не рантайм.** `docs/research/` остаётся аудит-следом; игра читает только
  `open_football.sqlite` и `assets/data/*.json`.
