# Пакет матча

**Статус на 2026-10-30:** выбранные команды доходят до C++ готовым пакетом; C++ строит матч из
пакета и **не читает базу для матча**. Тикет —
`.scratch/gpf-game-shell/issues/06-paket-matcha-vybrannye-komandy.md`; каталог — [[каталог-команд]],
статы/формация — [[статы-и-формация]], runtime — [[порт-gdextension]].

## Поток

`Select Teams` → `scenes/prematch.tscn` (состав, скамейка, позиции на схеме, длина матча,
сложность) → `scenes/gpf_slice.tscn`.

- `scripts/ui/prematch.gd` строит пакет через `MatchPackage` и кладёт его в `ShellState.match_package`.
- `scripts/ui/lineup_editor.gd` (`LineupEditor`) — редактор одной команды: 11 стартовых на схеме,
  скамейка и перетаскиваемые точки. Модель — `scripts/data/match_lineup.gd` (`MatchLineup`).
  Выбор кликом: первый игрок запоминается, второй — меняется с ним местами; работает и внутри
  одного списка, и между стартовыми/скамейкой.
- `scripts/match/gpf_slice.gd` берёт пакет из `ShellState` и вызывает
  `GpfRuntimeNode.set_match_package(pkg)` до `restart_match()`. Встроенных команд нет: без пакета
  сцена матча возвращает в выбор команд. **Start Match** в главном меню всегда ведёт в прематч
  (если команды выбраны) или в выбор команд — пакет собирается заново на `Kick Off`, старый не
  переиспользуется.
- `GpfRuntimeNode` хранит `TeamDataRaw` обеих команд в памяти процесса, поэтому F4 и меню «начать
  заново» перезапускают матч с тем же пакетом без повторного чтения базы (новый `Kick Off` из
  прематча собирает пакет заново).

## Редактор состава (`MatchLineup`)

`MatchLineup.from_squad(squad)` берёт состав из `TeamCatalog.load_squad()`: первые 11 игроков —
стартовые (в порядке формации), остальные — скамейка. Модель умеет:

- `set_starter(slot, player_id)` — поставить игрока со скамейки в слот (стартовый уходит на
  скамейку) или поменять местами двух стартовых;
- `swap_players(a, b)` — поменять местами любую пару: двух стартовых, двух запасных или
  стартового с запасным;
- `clear_slot(slot)` — снять стартового (для проверки невалидных состояний);
- `move_position(slot, Vector2)` — перетащить точку на схеме, координаты клампятся в -1..1 и
  пишутся и в `position`, и в `database_position`;
- `validate()` — ровно 11 стартовых, без дублей, все из состава, 11 слотов формации, слот с ролью
  `GK` не пустой. Полевого игрока в рамку ставить можно (как в реальном футболе) — он просто будет
  играть на позиции вратаря со своими статами; `warning()` предупреждает об этом, не блокируя
  `Kick Off`. Ошибка — текст для UI, он же блокирует `Kick Off`.

`MatchPackage.build(..., lineups)` принимает `{"home": MatchLineup, "away": MatchLineup}`.
Стартовые пишутся в `players` **первыми**, скамейка — после: C++ активирует первых 11 в порядке
пакета (`Team::Team`), поэтому на поле выходят выбранные игроки. `formation` берётся из модели
(роли и перетащенные позиции); `players` по-прежнему содержит весь состав, чтобы работали замены.
Невалидная модель отклоняется и на уровне билдера (`"Home lineup: ..."`).

## Схема пакета

`scripts/data/match_package.gd` (`MatchPackage`), версия 1:

```
{
  version: 1,
  options: { duration: float(0..2), difficulty: float(0..1) },
  home: team, away: team
}
team = {
  database_id, name, short_name, logo_url, kit_url,
  color1/color2: Vector3,                    # те же значения, что GetVectorFromString
  formation_xml, formation_factory_xml, tactics_xml, tactics_factory_xml,
  formation: [ { role, database_position: Vector2, position: Vector2 } × 11 ],
  players: [ { database_id, first_name, last_name, role, skin_color, hair_style,
               hair_color, height, strong_foot, tm_id, stats{22} } ]
}
```

- Пакет несёт **весь состав** (не только стартовые 11): C++ создаёт и запасных, чтобы работали
  замены; активны первые 11 по `formationorder`.
- `stats` — итоговые статы из `PlayerStats` ([[статы-и-формация]]), их C++ использует напрямую.
  Если карта пустая/неполная, `PlayerData::Init` добирает недостающие значения из `profile_xml`
  (защита от старых пакетов).
- `formation[].position` — уже нормализованная Godot-версией `Formation` позиция; C++ берёт её
  как есть (`TeamData::InitFromRaw` использует `raw.formation`, если там ровно 11 слотов). Без
  формации C++ парсит `formation_xml`, как раньше.
- `logo_url`/`kit_url` уже с префиксом `databases/default/`, как их отдавал C++-загрузчик из базы.
- `options.duration` — оригинальный `match_duration` (0.0 ускоряет часы в 20 раз; в игре 0.5/1.0/1.5),
  `options.difficulty` — `match_difficulty`; C++ применяет их к конфигу перед созданием `Match`.

## C++-сторона

Изменения в чекауте GameplayFootball `of_port`:

- `PlayerDataRaw.stats` — готовые статы; `TeamDataRaw.formation` — готовые роли/позиции;
  `MatchData(TeamDataRaw&, TeamDataRaw&)` строит модель без SQL.
- `GpfRuntimeNode::set_match_package(Dictionary)` валидирует пакет (2 команды, 11 слотов формации,
  ≥11 игроков, непустые статы) и складывает в `TeamDataRaw`; `start_match()` требует пакет, иначе
  возвращает `false` с `last_error`. Legacy-путь `MatchData(int, int)` в мост больше не подключён.
- `MatchData` создаётся в `start_match` из пакета; `TeamData(int)`/`PlayerData(int)` (чтение базы)
  остаются только для меню самого оригинала.
- `debug_get_formation(team_id)` отдаёт роли/позиции из живого `TeamData` — им проверяется, что на
  поле расстановка из пакета.

## Случайная последовательность

C++ больше не тратит `random(1,4)` на выбор цвета кожи при чтении базы (по одному на игрока,
включая запасных) — эти значения теперь приходят из пакета. Как и раньше, мост делает
`blunted::randomize(seed)` прямо перед созданием матча, поэтому *после* reseed поток RNG прежний;
сдвиг — в потреблении до reseed, плюс сама игра могла пойти иначе из-за чуть других значений
`float`/`double` в статах и формации (проверка геймплея — тикет 07). В standalone-игре без
per-match reseed удаление этих вызовов сдвигает поток явно.

`check_gpf_rematch`, `check_gpf_setpieces` (все сценарии), `check_gpf_shootout`,
`check_gpf_game_shell`, `check_gpf_slice_ui` — PASS.

Тесты `check_gpf_*` собирают пакет тем же `MatchPackage` через `tests/match_package_fixture.gd` и
передают его в runtime до `start_runtime_now()`; `check_gpf_full_match`/`90_winner` дополнительно
выравнивают счёт в концовке, потому что с новыми данными AI-vs-AI больше не заканчивает матч
ничьей/нужным счётом гарантированно.
