# Система настроек

Порт `src/menu/settings.cpp` из GameplayFootball на дизайн-систему оболочки.
Один экран (`SettingsScreen`) используется и в паузе матча, и в предматчевом хабе:
в хабе пункт **SYSTEM SETTINGS** (бывший MATCH OPTIONS) открывает его поверх хаба,
в паузе — пункт **SETTINGS**.

Файлы: `scenes/ui/settings_screen.tscn` + `scripts/ui/settings_screen.gd`,
хранилище и мост — `scripts/data/settings_store.gd`.

## Плитки

Сетка 4×2 (как остальные bento-экраны), внутри — страница со списком строк и
хлебными крошками:

| Плитка | Содержимое |
|---|---|
| GAMEPLAY | 12 слайдеров 0..1: short/through/high pass direction+power, shot direction, curl spin (0..300) и aim (0..0.3 рад), agility, acceleration, 8-way quantization |
| CONTROLS | KEYBOARD (16 биндингов) и GAMEPADS → button mapping (14 кнопок) / function setup (switch, special, sprint, dribble; on the ball; off the ball) |
| GRAPHICS | список разрешений в вариантах windowed/fullscreen, применяется сразу через `DisplayServer` |
| AUDIO | master volume через `AudioServer` (+ `audio_volume` в C++ config) |
| CAMERA | zoom/height/fov/horizontal angle, живьём через `Match::SetCameraParams`; в паузе локального матча превью обновляется сразу. В сети камера по умолчанию идёт из снапшота хоста; как только клиент двигает свои настройки, `SetRemoteCameraOverride(true)` заставляет его считать камеру локально из синхронизированных позиций (как оригинальный `CameraPage::UpdateCamera`) |
| MATCH OPTIONS | difficulty + match length (список 5/7/10/12/15 минут реального матча, влево/вправо); в хабе редактируется, в паузе read-only («applies to the next match») |
| SIDE SELECTION | в локальном хабе — оверлей поверх настроек; в локальном матче настройки гаснут, side select открывается вместо них (без затемнения матча) и возвращает настройки при закрытии; commit вызывает `refresh_human_controllers`; в сети — mirrored side select, в сетевом хабе плитка выключена |

Слайдерные страницы (Gameplay/Camera/Audio/Options) — одна колонка с
прокруткой (фокус подтягивает строку, колесо мыши листает, справа индикатор).
Клавиша `select`/`start` намеренно не переназначаются: Tab владеет меню
исполнителя стандарта, Enter — подтверждение в оболочке.

## Хранение

`SettingsStore` пишет `user://settings.cfg` (`ConfigFile`), секции
`gameplay`, `camera`, `audio`, `graphics`, `keyboard`, `gamepad`.
Файл читается лениво и сохраняется при закрытии экрана. Значения по умолчанию —
из `gamedefines.hpp`.

## Применение

- **GAMEPLAY/CAMERA** — мост `GpfRuntimeNode.set_gameplay_settings` /
  `set_camera_settings` пишет ключи `gameplay_*` / `camera_*` в
  `GetConfiguration()`; C++ читает assists на каждый пас/удар, agility/acceleration
  — каждый `HumanoidBase::Process`, камеру — через `SetCameraParams` (живой матч).
- **GAMEPADS** — `set_gamepad_settings` раскладывает mapping на все
  `HIDGamepad` (сырые SDL-кнопки, которые шлёт слайс). Кодировка:
  `>= 0` кнопка, `-(2*axis+1)`/`-(2*axis+2)` — отрицательная/положительная полуось.
- **KEYBOARD** — слайс больше не держит `BUTTONS`: `gpf_slice._handle_key` берёт
  функции из `SettingsStore.functions_for_key(keycode)`.
- **GRAPHICS/AUDIO** — Godot-окно и мастер-шина; применяются на главном меню и
  сразу при изменении.
- Настройки применяются к рантайму после регистрации геймпадов и до
  `restart_match()` (`gpf_slice._ready` / `_start_fresh_match`).

## Смена сторон

`SettingsSideSelect` пишет выбранные стороны в `ShellState.controllers` и шлёт
`controllers_changed`; прематч обновляет состояние хаба. При открытии
**Team Management** план пересобирается с актуальными human-командами
(`prematch._on_game_plan_requested`), иначе редактировалась бы прежняя команда.

В матче источник истины — C++: `gpf_slice._human_teams()` и `_pause_team()`
читают `runtime.get_controller_setup()`, а не `ShellState` (после сетевого
mirrored side select он устаревает). Поэтому план из паузы и карточка состава в
паузе открываются на новой стороне.

В локальном матче Side Selection больше не выключен: пауза открывает тот же
`SettingsSideSelect` поверх настроек, commit пишет `ShellState` и зовёт
`runtime.refresh_human_controllers()` (C++ `Match::UpdateControllerSetup`), так
что управление переезжает на выбранную команду, а освобождённую сторону
забирает AI. Сетевые стороны по-прежнему меняет host через mirrored lobby.

## Тесты

- `tests/check_settings_screen.gd` — плитки, одна колонка со скроллом, ремап
  клавиши, персист и масштабирование curl-значений для C++.
- `tests/check_settings_animation.gd` — окно (не headless): fade/scale хаба,
  подстраниц настроек и оверлея Side Selection при открытии/закрытии.
- `tests/check_gpf_pause.gd` — вход/выход из настроек в паузе.
- `tests/check_gpf_camera_pause.gd` — смена camera setup на паузе сразу двигает
  презентационную камеру (кадр не замирает до resume).
- `tests/check_match_hub_view.gd`, `tests/check_prematch_ui.gd`,
  `tests/check_gpf_net_ui.gd` — плитка SYSTEM SETTINGS, MATCH OPTIONS и SIDE SELECTION.
