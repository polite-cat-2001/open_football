# Ввод и контроллеры

**Статус на 2026-11-03:** экраны выбора стороны/устройства (`SideSelectPage`,
`GameplayFootball-of_port/src/menu/sideselect.cpp`) и выбора команд (`TeamSelectPage`) переведены
на дизайн-систему и вынесены в общие `SideSelectView`/`TeamSelectView`; локальные
`controller_select`/`team_select` и сетевые `network_sides`/`network_lobby` — только адаптеры.
Матч получает настройку контроллеров и сырые оси/кнопки выбранного устройства; ввод идёт в
`HumanGamer` C++, а не в общее клавиатурное состояние.

## Оболочка (Godot)

- `scenes/ui/side_select_view.tscn` / `scripts/ui/side_select_view.gd` (`SideSelectView`) —
  общий визуал/раскладка/ввод: шапка `SIDE SELECT` 56 px, body 691.2 px с градиентом,
  вертикальные `HOME`/`AWAY`, трек устройств 112×112 с edge inset 260 px и tween 340 мс
  (крупнее и с меньшим ходом, чем в прототипе), ready-бейдж на устройстве. Тема — только на
  корне экранов, не глобально.
- `scenes/controller_select.tscn` / `scripts/ui/controller_select.gd` — локальный адаптер:
  `InputSetup.available_devices()` + `ShellState.controllers`, одинокий keyboard стартует home,
  несколько устройств — в центре, ready требуется от каждой не-центральной строки. Управление:
  `Left/Right` двигает строку **своего** устройства, `Enter`/`A` — ready, `Esc`/`B` — снять
  ready/выйти. Ready на центральной (spectator) строке запрещён с подсказкой
  «Choose a side first». **Hot-plug:** адаптер слушает `Input.joy_connection_changed` и
  пересобирает строки через `_sync_participants()` — новый геймпад появляется в центре,
  отключённый исчезает, существующие строки сохраняют side/ready, тона переиндексируются.
  Порядок строк сверху вниз — **порядок подключения**: клавиатура всегда первая, новый геймпад
  добавляется в конец, а не по номеру device id; при отключении оставшиеся сохраняют порядок.
- `scenes/network_sides.tscn` / `scripts/ui/network_sides.gd` — сетевой адаптер: снапшот лобби
  (имена, YOU, ready, device), `resume_mode` поверх замороженного матча (не выходит из сессии),
  host-authoritative commit, resume-голосование, disconnect/join статусы. Действия идут в
  `NET_SHELL`, а не в `ShellState`.
- `scenes/ui/team_select_view.tscn` / `scripts/ui/team_select_view.gd` — общий экран выбора
  команд: две карточки HOME/AWAY, блоки Country/Team/Competition, фокус, ready, статус и легенда.
  Локальный `team_select` и сетевой `network_lobby` — тонкие адаптеры. `Up/Down` — блок,
  `Left/Right` — значение, `A/Enter` — ready, `B/Esc` — снять ready/назад. В 1P активна одна
  панель (вторая видна приглушённой), в 2P каждое устройство правит свою (`moved_gamepad`),
  в сети — только свои chooser-слоты; если оба слота у одного игрока, `Tab` переключает панель.
  Мышь инертна; `V` (состав) с этого экрана убран.
- Ввод экрана — только через `UiNav` (autoload): направления/подтверждение/отмена и автоповтор
  для клавиатуры и геймпада. `UiNav.last_device_id()`/`last_input_gamepad()` позволяют отличить
  клавиатуру от конкретного геймпада в 2P. Мышь на этом экране **инертна** — кликов ready/back
  и фокуса нет (решение владельца, отступление от исходного ТЗ).
- Иконки — белые SVG `assets/ui/icons/{keyboard,gamepad}.svg`, тонируются по номеру участника
  (`UiTokens.SIDE_TONES`: blue/magenta/orange/green); старые PNG `assets/ui/controller/*` и
  Alegreya на этом экране больше не используются.
- Поток: **Quick Match → Controller Select → Team Select → Kit Select → Match Hub**. Controller
  Select всегда ведёт в Team Select: выбранная ранее пара восстанавливается на экране команд, но
  не пропускает его.
- `scenes/kit_select.tscn` / `scripts/ui/kit_select.gd` — локальный адаптер общего
  `KitSelectView`: 1P по очереди выбирает home и away, 2P — каждое устройство свою; `Left/Right`
  — комплект, `A/Enter` — ready, `B/Esc` — снять/назад. Сетевой адаптер —
  `scenes/network_kit_select.tscn`: только свои chooser-слоты, `Tab`/LB-RB при двух слотах;
  киты локальные, не синхронизируются; после ready открывается `network_match_hub` (та же фаза 2).
- `scenes/prematch.tscn` / `scenes/network_match_hub.tscn` — общий `MatchHubView`: Left/Right и
  Tab/LB-RB листают command-ячейки, A/Enter активирует, B/Esc — назад/закрывает оверлей.
  `TEAM MANAGEMENT` открывает `GpfGamePlan` (стрелки/D-pad, A/Enter, Y/Tab, X — отмена замены);
  `MATCH OPTIONS` — Up/Down строка, Left/Right значение; `EXIT` — выход в главное меню
  (в сети с закрытием LAN-сессии).
  В 1P Start сразу собирает пакет; в 2P каждое локальное устройство голосует Start, повторное
  нажатие/Back отзывает голос, матч стартует при `x/y`. В сети host правит options и стартует,
  client ждёт `MatchSetup`; мышь работает (hover/click/слайдеры).
- `scripts/data/input_setup.gd` (`InputSetup`) — перечисление устройств
  (`Input.get_connected_joypads()` + клавиатура), нормализация выбора и перевод в setup для C++.
  `apply_to_runtime()` возвращает `{setup, slots}`, где `slots` — карта
  `godot_device_id -> cpp_slot`.
- `ShellState.controllers` — подтверждённые участники:
  `{side: "home"|"away", kind: "keyboard"|"gamepad", device: int, name: String}`.
  `controllers_configured` отличает пользовательский выбор от fallback по умолчанию. Сейчас
  экран поддерживает несколько устройств (задел под 2P), но матчевая презентация/HUD ещё 1P.
- `scripts/match/gpf_slice.gd` — `_configure_input()` регистрирует геймпады в C++ и передаёт setup
  **до** `restart_match()`; хранит `input_slots` и маршрутизирует `InputEventJoypadButton` /
  `InputEventJoypadMotion` в `set_gamepad_button` / `set_gamepad_axis`. В открытых меню (повтор,
  перерыв, конец серии, меню исполнителя) A/Start/B/D-pad транслируются в Enter/Esc/стрелки, а
  Back/Select — в Tab. Вне меню Back открывает меню исполнителя.

## C++ (GDExtension-мост)

- `GpfRuntimeNode::register_gamepad(godot_device_id)` — создаёт extension-owned SDL virtual
  joystick и возвращает его id (`-1` при ошибке). Идемпотентен по id устройства.
- `set_controller_setup([{side: -1|1, kind, slot}])` — сохраняет setup; `start_match()` строит
  `SideSelection` и кладёт его в `MenuTask`. `apply_controller_setup()` переприменяет его перед
  каждым тиком, поэтому очистка меню и hot-plug не снимают `HumanGamer`.
- `set_gamepad_button(slot, button, pressed)` / `set_gamepad_axis(slot, axis, value)` — `slot` здесь
  id виртуального джойстика; сырые индексы Godot `JoyButton`/`JoyAxis` совпадают с семантическими
  SDL3, поэтому в `UserEventManager::InputSDLEvent` уходит synthetic `SDL_EVENT_GAMEPAD_*`.
- GameplayFootball (`of_port`) не меняется: виртуальный джойстик попадает в штатный
  `RefreshGamepads`, для него создаётся обычный `HIDGamepad`, и `HumanController` читает ввод через
  `IHIDevice`, как у физического геймпада.
- `get_human_player_id()` / `select_player()` ищут по обеим командам: человек может играть за away.
- Раскладка геймпада по умолчанию (PES-подобная): A — короткий пас, B — высокий, X — удар,
  Y — длинный, LB — смена игрока, L2 — special, RB — спринт, R2 — дриблинг, Select — меню
  исполнителя, Start — подтверждение в меню. Клавиатура — стрелки/WASD/E/C/Q.

## Проверка

- `tests/check_controller_select_ui.gd` (headless): реальный экран через `UiNav`; клавиатура в
  списке, `Left/Right` двигает home → centre → away, центр нельзя подтвердить, `Enter` на away
  коммитит setup в `ShellState` и открывает выбор команд. `check_controller_select_flow.gd`
  отдельно проверяет, что уже выбранная пара не пропускает Team Select. Проверяются геометрия 56/691.2/84/104,
  позиции 104/698/1292, тон по индексу и hot-plug: добавление/удаление строки геймпада, старт
  в центре и переиндексация тона.
- `tests/check_side_select_view.gd` (headless): общий view с фикстурой 2P — куи, ready-бейдж,
  tween 340 мс, сигналы `UiNav`, resume-оверлей, имена сети и scale 2/3 на 1280×720.
- `tests/check_team_select_view.gd` (headless): общий TeamSelectView — геометрия карточек/блоков,
  фокус и cues, ready, idle-панель, клавиатура и `moved_gamepad`, `Tab` между слотами, error/retry,
  scale 2/3.
- `tests/check_team_select_ui.gd` (headless): локальный экран — lazy-каталог, ready home → CPU away,
  ready away → прематч, ошибка базы и повторная загрузка.
- `tests/check_gpf_input.gd` (headless): клавиатура на home и виртуальный геймпад на away;
  setup доходит до C++, `HumanGamer` привязан к нужному устройству и стороне, управляемый игрок
  реально смещается от ввода (`get_player_pose().pos`).
- `tests/check_prematch_ui.gd` — setup из `ShellState` доходит до runtime, геймер садится на выбранную
  сторону. `check_prematch_vote` — 2P-голосование Start, `check_match_hub_view` — UiNav/мышь и
  command-ячейки хаба. `check_gpf_game_shell` и `check_gpf_net_ui` проходят через
  controller/network sides.
- **Ручная проверка геймпада** (нужна один раз на железе): подключить геймпад → **Quick Match** →
  на экране выбора стороны выбрать HOME/AWAY (стик/D-pad), **A** — ready. Проверить кикофф,
  перерыв (`Start`/`A`) и меню исполнителя (`Back`).
