# Ввод и контроллеры

**Статус на 2026-10-30:** экран выбора стороны/устройства портирован из оригинала
(`SideSelectPage`, `GameplayFootball-of_port/src/menu/sideselect.cpp`) в
`scenes/controller_select.tscn`. Матч получает настройку контроллеров и сырые оси/кнопки
выбранного устройства; ввод идёт в `HumanGamer` C++, а не в общее клавиатурное состояние.
Тикет — `.scratch/gpf-game-shell/issues/10-controller-side-select-geympad.md` (issue #22).

## Оболочка (Godot)

- `scenes/controller_select.tscn` / `scripts/ui/controller_select.gd` — порт `SideSelectPage`:
  колонки **Team 1 / Team 2**, подпись **choose your side**, по иконке на каждое локальное
  устройство (`assets/ui/controller/keyboard_small.png` / `controller_small.png`), зелёная
  ready-галочка (`scripts/ui/ready_mark.gd`), шрифт Alegreya
  (`assets/ui/fonts/AlegreyaSansSC-ExtraBold.ttf`). Управление: `Left/Right` — сторона,
  `Enter`/`A` — ready, `Esc`/`B` — снять ready/выйти; стик и D-pad геймпада работают с задержкой
  250 мс, как в оригинале. Геймер может играть за Team 1 или Team 2.
  Отступления от оригинала: ready на центральной (spectator) строке запрещён с подсказкой
  «Choose a side first»; при нескольких устройствах все строки стартуют в центре (в оригинале
  первый геймпад сразу home), чтобы неактивная строка не блокировала чужой ready.
- Поток как в оригинале: **Start Match → Controller Select → Team Select → PreMatch**. Если пара
  команд уже выбрана, controller screen ведёт сразу в прематч (уступка оболочке). Кнопка
  **Select Teams** остаётся ярлыком в выбор команд; тогда действует setup по умолчанию
  (клавиатура, home).
- `scripts/data/input_setup.gd` (`InputSetup`) — перечисление устройств
  (`Input.get_connected_joypads()` + клавиатура), нормализация выбора и перевод в setup для C++.
  `apply_to_runtime()` возвращает `{setup, slots}`, где `slots` — карта
  `godot_device_id -> cpp_slot`.
- `ShellState.controllers` — подтверждённые участники:
  `{side: "home"|"away", kind: "keyboard"|"gamepad", device: int, name: String}`.
  `controllers_configured` отличает пользовательский выбор от fallback по умолчанию. Сейчас
  экран поддерживает несколько устройств (задел под 2P), но матчевая презентация/HUD ещё 1P.
- `scripts/match/gpf_slice.gd` — `_configure_input()` регистрирует геймпады в C++ и передаёт setup
  **до** `restart_match()`; хранит `input_slots` и маршрутизирует `InputEventJoypadButton` /
  `InputEventJoypadMotion` в `set_gamepad_button` / `set_gamepad_axis`. В открытых меню (повтор,
  перерыв, конец серии, меню исполнителя) A/Start/B/D-pad транслируются в Enter/Esc/стрелки, а
  Back/Select — в Tab. Вне меню Back открывает меню исполнителя.

## C++ (GDExtension-мост)

- `GpfRuntimeNode::register_gamepad(godot_device_id)` — резервирует виртуальный слот, возвращает
  его (`-1`, если слоты кончились). Идемпотентен по id устройства.
- `set_controller_setup([{side: -1|1, kind, slot}])` — сохраняет setup; `start_match()` строит
  `SideSelection` и кладёт его в `MenuTask`.
- `set_gamepad_button(slot, button, pressed)` / `set_gamepad_axis(slot, axis, value)` — сырые
  SDL-совместимые индексы (Godot `JoyButton`/`JoyAxis` совпадают с семантическими SDL3).
- `UserEventManager::AddVirtualGamepad` / `SetJoystickAxis` (of_port) — виртуальный слот без
  `SDL_Gamepad`; `RefreshGamepads` создаёт для него обычный `HIDGamepad`, поэтому штатный
  `HumanController` читает ввод через `IHIDevice`, как у физического геймпада.
- `Match::UpdateControllerSetup` предпочитает `MenuTask::shellSides` (setup хоста), иначе — меню.
  Поэтому очистка `MainMenuPage` и hot-plug не снимают `HumanGamer`.
- `get_human_player_id()` / `select_player()` ищут по обеим командам: человек может играть за away.
- Раскладка геймпада по умолчанию (PES-подобная): A — короткий пас, B — высокий, X — удар,
  Y — длинный, LB — смена игрока, L2 — special, RB — спринт, R2 — дриблинг, Select — меню
  исполнителя, Start — подтверждение в меню. Клавиатура — стрелки/WASD/E/C/Q.

## Проверка

- `tests/check_controller_select_ui.gd` (headless): экран открывается, клавиатура в списке,
  `Left/Right` двигает home → centre → away, центр нельзя подтвердить, `Enter` на away коммитит
  setup в `ShellState` и открывает выбор команд.
- `tests/check_gpf_input.gd` (headless): клавиатура на home и виртуальный геймпад на away;
  setup доходит до C++, `HumanGamer` привязан к нужному устройству и стороне, управляемый игрок
  реально смещается от ввода (`get_player_pose().pos`).
- `tests/check_prematch_ui.gd` — setup из `ShellState` доходит до runtime, геймер садится на выбранную
  сторону. `check_gpf_game_shell` проходит через controller screen.
- **Ручная проверка геймпада** (нужна один раз на железе): подключить геймпад → **Start Match** →
  на экране выбора стороны выбрать Team 1/Team 2 (стик/D-pad), **A** — ready. Проверить кикофф,
  перерыв (`Start`/`A`) и меню исполнителя (`Back`).
