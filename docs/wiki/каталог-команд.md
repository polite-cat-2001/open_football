**Статус на 2026-10-30:** Godot владеет каталогом лиг, команд и игроков, читая
`database.sqlite` напрямую. C++-каталог для экрана выбора больше не используется; выбранные
команды уходят в матч готовым пакетом — [[пакет-матча]]. Контекст трека — [[порт-gdextension]];
спека набора: `.scratch/gpf-game-shell/spec.md`, тикет — `issues/04-sqlite-katalog-lig-i-komand.md`.

## SqliteReader

Почему свой парсер: Godot не умеет SQLite, а тянуть бинарный GDExtension-аддон в публичный
репозиторий ради двух таблиц не хочется. Читатель на GDScript ходит по файлу страницами
(`FileAccess.seek` + `get_buffer`) и разбирает ровно то, что нужно каталогу.

- Поддерживаются только table b-tree (0x0D лист, 0x05 interior), overflow-страницы и все serial
  types. Индексы, views, `WITHOUT ROWID` и запись не поддерживаются.
- `select_all(table, wanted)` возвращает массив словарей; `wanted` отсекает тяжёлые колонки
  (`formation_xml`, `tactics_xml`), которые каталогу не нужны.
- **Грабли:** колонка `INTEGER PRIMARY KEY` в payload хранится как NULL (serial type 0), её значение
  — это rowid ячейки. Читатель берёт имя такой колонки из `CREATE TABLE` и подставляет rowid.
- **Грабли:** `country_id`/`tier` бывают NULL (лига `National Teams`), поэтому каталог приводит
  числа через null-safe `_int()`.
- 193 МБ база: лиги+команды читаются ~130 мс; `players` (125 402 строки) — ~3 с, поэтому каталог
  игроков должен читать только нужные колонки/команды.

## TeamCatalog

- Корень данных: аргумент `load_data_root(root)`, иначе `GPF_DATA_ROOT`, иначе
  `DEFAULT_DATA_ROOT` (`C:/Users/Egor/Desktop/projects/GameplayFootball-of_port/data`) — тот же
  порядок, что у `GpfRuntimeNode`.
- Путь к базе: `<root>/databases/default/database.sqlite`.
- `leagues` отсортированы по стране → tier → имени; лиги без страны (National Teams) — в конце.
  `teams_for_league(id)`, `team_by_id(id)`, `league_by_id(id)`.
- Ошибки: `Team database not found at <path>. Set GPF_DATA_ROOT...` и
  `Team database could not be read: <path> (<detail>).`; пустая/полузагруженная база откатывается,
  каталог остаётся пустым.
- `read_manifest_coverage(root)` читает `coverage` из `manifest.json` — тест сверяет с ним число
  лиг и команд, а не хардкодит версию данных.

## ShellState и экран

- `ShellState` — статический класс (`home_team`, `away_team`, `set_teams`, `has_selection`,
  `match_options`, `match_package`, `clear`). Статика, а не autoload: headless `-s` не создаёт
  autoload'ы, а тесты должны идти тем же путём, что и игра. Прематч и матч читают отсюда.
- Экран выбора команд — порт оригинального `TeamSelectPage`: две панели **Player 1/Player 2**,
  в каждой карусели **Country select / Competition select / Team select** и кнопка **Ready**.
  `Up/Down` — уровень, `Left/Right` — выбор, `Enter/A` — дальше, `Esc/B` — назад; `V` — состав
  выбранной команды. «National Teams» пропускает уровень лиги. При одном устройстве после Ready
  первой стороны панель CPU-соперника открывается для выбора второй команды; при двух локальных
  устройствах обе панели активны параллельно. По Ready обеих сторон `ShellState.set_teams(...)`
  и переход в прематч.
- Прематч — порт оригинального `PreMatchPage`: заголовок `Home vs Away`, семь вкладок
  **Kit / Stadium / Kick-off / Game plan / Options / Camera / System** (по умолчанию Kick-off).
  Kick-off — два столбца стартовых фамилий, **Edit lineups** (оверлей `LineupEditor`) и **Start
  match**. Options — слайдеры сложности и длины матча; Kit — выбор полос с превью; остальные
  вкладки показывают оригинальные подписи/кнопки-заглушки. Start собирает пакет (`MatchPackage`)
  и открывает матч — [[пакет-матча]].
- Если база не открылась, экран показывает сообщение об ошибке и не даёт начать матч.
- Вход: кнопка **Select Teams** в главном меню → выбор команд → прематч. **Start Match** ведёт
  по оригинальному пути **controller/side select → team select → pre-match**; встроенной пары
  команд нет, старый пакет не переиспользуется.
- UI-правило набора: экраны меню портируются из `GameplayFootball-of_port/src/menu/...`, а не
  проектируются заново (см. `spec.md`, «UI-политика» в каждом тикете).
