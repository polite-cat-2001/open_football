# Каталог команд и экран выбора

**Статус на 2026-10-29:** Godot владеет каталогом лиг, команд и (дальше) игроков, читая
`database.sqlite` напрямую. C++-каталог для экрана выбора больше не используется; матч пока
стартует со старыми id (`MenuTask::SetTeamIDs("3", "8")`), пакет матча — следующий тикет.
Контекст трека — [[порт-gdextension]]; спека набора: `.scratch/gpf-game-shell/spec.md`,
тикет — `issues/04-sqlite-katalog-lig-i-komand.md`.

## SqliteReader

Почему свой парсер: Godot не умеет SQLite, а тянуть бинарный GDExtension-аддон в публичный
репозиторий ради двух таблиц не хочется. Читатель на GDScript ходит по файлу страницами
(`FileAccess.seek` + `get_buffer`) и разбирает ровно то, что нужно каталогу.

- Поддерживаются только table b-tree (0x0D лист, 0x05 interior), overflow-страницы и все serial
  types. Индексы, views, `WITHOUT ROWID` и запись не поддерживаются.
- `select_all(table, wanted)` возвращает массив словарей; `wanted` отсекает тяжёлые колонки
  (`formation_xml`, `tactics_xml`), которые каталогу не нужны.
- **Грабли:** колонка `INTEGER PRIMARY KEY` в payload хранится как NULL (serial type 0), её значение
  — это rowid ячейки. Читатель берёт имя такой колонки из `CREATE TABLE` и подставляет rowid.
- **Грабли:** `country_id`/`tier` бывают NULL (лига `National Teams`), поэтому каталог приводит
  числа через null-safe `_int()`.
- 193 МБ база: лиги+команды читаются ~130 мс; `players` (125 402 строки) — ~3 с, поэтому каталог
  игроков должен читать только нужные колонки/команды.

## TeamCatalog

- Корень данных: аргумент `load_data_root(root)`, иначе `GPF_DATA_ROOT`, иначе
  `DEFAULT_DATA_ROOT` (`C:/Users/Egor/Desktop/projects/GameplayFootball-of_port/data`) — тот же
  порядок, что у `GpfRuntimeNode`.
- Путь к базе: `<root>/databases/default/database.sqlite`.
- `leagues` отсортированы по стране → tier → имени; лиги без страны (National Teams) — в конце.
  `teams_for_league(id)`, `team_by_id(id)`, `league_by_id(id)`.
- Ошибки: `Team database not found at <path>. Set GPF_DATA_ROOT...` и
  `Team database could not be read: <path> (<detail>).`; пустая/полузагруженная база откатывается,
  каталог остаётся пустым.
- `read_manifest_coverage(root)` читает `coverage` из `manifest.json` — тест сверяет с ним число
  лиг и команд, а не хардкодит версию данных.

## ShellState и экран

- `ShellState` — статический класс (`home_team`, `away_team`, `set_teams`, `has_selection`,
  `clear`). Статика, а не autoload: headless `-s` не создаёт autoload'ы, а тесты должны идти тем же
  путём, что и игра. Следующие шаги (прематч, пакет матча) читают отсюда.
- Экран: слева лиги (`Страна — Лига`), в центре команды выбранной лиги, справа слоты Home/Away и
  кнопки `Set as home` / `Set as away`. `Start Match` активен только когда выбраны обе команды и
  делает `ShellState.set_teams(...)` перед сменой сцены.
- Если база не открылась, экран показывает сообщение об ошибке и не даёт начать матч.
- Вход: кнопка **Select Teams** в главном меню (прямой **Start Match** остаётся быстрым путём до
  тикета 06).
