# Оригинальный runtime внутри Godot

**Labels:** `wayfinder:research`

**Blocked by:** None

**Status:** done

**Resolution:** [Отчёт об исследовании](../research/01-original-runtime-inside-godot.md) — оригинальные библиотеки целиком в одной GDExtension-DLL; `GameTask::ProcessPhase`/`PutPhase`; одна правка presentation clock; `Put` обязателен, потому что двигает AABB для `Process`; один runtime на процесс, без нового sim-thread.

## Question

Какой минимальный и безопасный способ запустить актуальный C++ GameplayFootball внутри GDExtension так, чтобы Godot только отображал состояние, а поведение оставалось оригинальным?

Нужно определить по исходникам, а не предположениями:

- какие существующие CMake-цели и исходники можно собрать для Windows x64 GDExtension;
- как повторить инициализацию `determinism_runner` с mock graphics/audio, не таща в Godot окно, OpenGL-рендер и меню как живой UI;
- как вызывать полный игровой контур `Process` / `PreparePutBuffers` / `FetchPutBuffers` / `Put` и получать интерполированное состояние на render-кадре без нового sim-thread;
- где получить позиции игроков, мяча и оригинальные позы 14 костей для внешнего представления;
- как обойти process-fatal `exit(1)`, глобальные менеджеры, повторный запуск и выгрузку DLL хотя бы на уровне явных ограничений первого среза;
- какие DLL, data-файлы, рабочая директория и настройки компилятора нужны, чтобы встроенный runtime сравнивался с эталоном на одной Windows x64 конфигурации.

Ответ должен дать точный список точек подключения, минимально необходимых изменений в C++ и порядок первого технического среза. Это исследование для решения, не реализация всего моста.
